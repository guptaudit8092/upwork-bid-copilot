# Proposal Playbook

Clients scan dozens of proposals and usually see only the first ~150–200 characters in their list. Win those characters, then prove it fast.

## Cover letter formula (120–180 words unless the post demands more)

1. **Hook (first 150–200 chars)** — name the client's specific problem + one concrete proof point. No "Hi, I'm…", no "I read your post with great interest".
2. **Two proof points** — real results, closest to their problem. Numbers only if the user actually has them.
3. **3-step plan** — how you'd start *their* project (week 1 / week 2 / ongoing, or assess → build → hand over).
4. **One closing question** — specific, easy to answer, invites a reply.

Address the contact by name **only** if a review or the post states it. Never guess a name.

### Hidden-instruction compliance
If the post says "start with the word X", "include keyword Y", or "list the mistakes in this post", that comes **first**, exactly as asked. For "find the mistakes" tests, list only mistakes you are certain of, with where each appears.

### When the post asks questions inside the description
If there are no formal screening questions but the description asks for answers, answer them inside the cover letter under a clear "Answers to your questions" heading — even if it pushes past 180 words.

## Screening answers

- 2–4 sentences each, one concrete example per answer.
- Answer the question asked; don't repeat the cover letter.
- If the user provides their own answer text, use it **verbatim**. Raise any concern (e.g. it contradicts a requirement) separately — don't silently edit.
- Unknown facts → `[confirm]` and ask. Never fill gaps with invented specifics.

## Rate guidance

- Respect the user's floor.
- Compare against the job's recorded bid range/average. Bidding far below the average on a senior role can signal "junior" — say so, but the user decides.
- For "propose your rate" posts, anchor near the average for strong fits.

## Attachments and Loom

- Always ask whether to attach anything.
- Suggest a short personalized Loom only for the top 1–2 bids per week, or when the job requires one. Offer a talk-track if the user wants help.

## Pre-submit checklist

- [ ] Dealbreakers flagged and accepted by the user
- [ ] Hook names their problem in the first 150–200 chars
- [ ] Hidden instruction/keyword obeyed
- [ ] Every claim is true and user-confirmed
- [ ] Every screening question answered
- [ ] Rate, boost and Connects cost shown
- [ ] Full preview shown and explicitly approved

## Template

```
[Required keyword/opening, if any]

Hi [Name from reviews],

[Their problem in one line] — [one proof point].

Two more relevant proof points:
- [Proof 1]
- [Proof 2]

How I'd start:
1. [Step 1]
2. [Step 2]
3. [Step 3]

[One specific question]?
```
